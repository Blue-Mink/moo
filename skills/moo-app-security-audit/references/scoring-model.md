# Moo 应用安全评分模型（八维，0-100 安全分）

> ✅ **评分口径（务必先读）**：本模型所有分数——八维分、综合分——**都是「安全分」**。
> **分数越高 = 越安全，分数越低 = 越危险。**
> - **100 分** = 该维度无风险 / 防护到位（安全基线）
> - **0 分** = 该维度极高风险（高危）
> - 等级：🟢 安全 = 放心装；🟡 中 = 了解风险后可装；🔴 危险 = 不建议装。
>
> 所以「权限 90 分」= 权限收敛得体面；「权限 10 分」= root + 自启 + 系统路径注入，危险。
> 「安全性」维度本质是「无恶意程度」：分高 = 没发现恶意迹象。

每个应用按八个层面独立打分，每维 0-100；再由八维合成综合安全分与等级。

## 八维定义

| 维度 | 0 分（极高风险） | 100 分（安全基线） |
|---|---|---|
| **安全性（恶意风险）Safety** | 后门 / 挖矿 / 数据窃取 / 反弹 shell / curl\|sh 下载执行 | 无任何恶意迹象 |
| **权限 Permission** | run-as root + systemd 自启 + /usr/local/bin 系统注入 | run-as package，最小权限 |
| **漏洞 Vulnerability** | 明文密码落盘 + 高危 CVE 依赖 + 弱默认口令 | 无硬编码凭据、无已知 CVE |
| **暴露面 Attack Surface** | 0.0.0.0 多端口 + docker.sock + host 网络 + 挂 / | 无对外端口、无危险挂载 |
| **供应链 Supply Chain** | 深度 fork 搬运 + 多源放大 + 上游不可信/不活跃 | 官方源 / 可信上游、无搬运 |
| **未知风险 Uncertainty** | 动态行为不可知 + latest 镜像漂移 + 无源码黑盒 | 全开源、可完整审计、版本固定 |
| **混淆/反分析 Obfuscation** | UPX/自定义壳 + 混淆器 + 反调试 + 无符号 | 无加壳、符号完整可审计 |
| **数据隐私/外联 Privacy/Exfil** | 上传敏感数据 + 遥测 + 外联 C2/未知服务器 | 无遥测、无外联、数据本地 |

## 打分规则（每维分档）

- **70-100**：安全（干净源码 / 最小权限 / 无端口 / 无外联）
- **40-70**：轻微（弱默认口令但可改 / 单端口 / 一级搬运 / strip 符号）
- **20-40**：中等（root 运行 / 危险挂载 / 深度搬运 / UPX 加壳 / 外联第三方）
- **0-20**：高危（恶意行为 / docker.sock + host / 明文凭据 / 数据窃取 / 上传即执行）

### 两维细化分档

**混淆/反分析 Obfuscation**（分越高 = 越透明可审计）：
- 90-100 无加壳、源码/符号完整
- 60-80 strip 符号（`-s -w` 编译，无 DWARF/nm 符号）
- 40-60 UPX 加壳（ELF `no section header` + `upx.sf.net` 标识）
- 20-40 自定义壳 / 混淆器（LLVM obfuscator、商业壳）
- 0-20 反调试 + 重度混淆 + 无符号

**数据隐私/外联 Privacy/Exfil**（分越高 = 越不碰你的数据）：
- 90-100 无外联、数据本地、无遥测
- 60-80 正常遥测/版本检查（HTTPS 官方域名）
- 40-60 外联第三方（统计/广告/CDN/未知 registry）
- 20-40 收集上传用户数据/设备信息（型号/序列号/MAC/系统版本/配置/日志/账号）
- 0-20 数据窃取（上传 /etc/shadow、环境变量、敏感文件）

> **重点核查「收集 + 设备信息/用户数据 + 上传」三连**：
> ① 收集什么——设备信息（型号 / MAC / 序列号 / 系统版本 / 硬件信息）；用户数据（配置 / 日志 / 账号 / 浏览记录）
> ② 上传到哪——官方域名 / 第三方 / 未知服务器
> ③ 是否明示——隐私政策 / 用户同意（未明示即扣分，分越低）

## 综合安全分

- **综合安全分 = min(八维) × 0.6 + avg(八维) × 0.4**（短板主导，兼顾整体）
- 或简化为：安全分 = 八维加权（权重：安全性（恶意风险）0.25 / 权限 0.15 / 漏洞 0.15 / 暴露面 0.1 / 供应链 0.1 / 未知风险 0.1 / 混淆反分析 0.05 / 数据隐私外联 0.1）

## 安全等级

| 综合安全分 | 等级 | 含义 |
|---|---|---|
| ≥ 70 | 🟢 安全 | 无明显问题，可放心安装 |
| 40-70 | 🟡 中 | 有需注意的风险点，了解后可装 |
| < 40 | 🔴 危险 | 有明显高危面，不建议安装 |

## 硬失败规则（恶意行为确认即判 0，不走加权）

以下任一项**被证实**（有文件 + 片段 + 行为链证据），**不是扣分而是直接判死**：

| 命中 | 处理 |
|---|---|
| **M1 病毒/蠕虫**（自我复制、批量感染其他应用文件） | 安全性 = **0**，综合 = **0**，🔴 **立即卸载** |
| **M2 木马/后门**（C2 回连、反弹 shell、无鉴权远控、写 authorized_keys、隐藏账号） | 安全性 = **0**，综合 = **0**，🔴 **立即卸载** |
| **M3 恶意脚本**（下载即执行、`base64 -d \| sh`、混淆执行外部输入） | 安全性 ≤ **10**，综合 ≤ **10**，🔴 不要安装 |
| **M4 数据破坏**（越界删除/覆盖/加密用户数据、wipe、勒索、清库/清表） | 安全性 = **0**，综合 = **0**，🔴 **立即卸载** |
| **M5 数据窃取**（读凭据/SSH/浏览器数据并外传） | 安全性 ≤ **10**，🔴 不要安装 |
| **M6 反取证**（清日志/清 history/隐藏痕迹） | 安全性 ≤ **30**，并叠加「未知风险」压低 |

> 硬失败时**不写「综合 X 分」**，直接写「🔴 恶意行为确认：{类别} —— 不建议安装/立即卸载」，
> 并给出证据位置；若只是「无法判断」（加壳/闭源），**不触发硬失败**，走未知风险扣分。

> 注：正常卸载自己的数据目录、清理自己的缓存/日志**不算** M4；只有越界删除他人数据才算。


## 未知风险（Uncertainty）专项

未知风险是「审计看不到」的部分，**打分要压低（20-40）**，不能当 100 分：

1. **动态/延迟行为**：静态分析看不到运行时外联；恶意逻辑可能条件触发（时间/环境/远程指令），审计时点 ≠ 运行时点。
2. **镜像漂移**：docker 镜像 `image: xxx:latest` 内容随时可变，审计的版本 ≠ 用户实际拉取的版本。
3. **供应链投毒窗口**：上游仓库/镜像在审计后被投毒，审计结论有时效性。
4. **依赖 CVE 未扫**：Go/Node/Java 依赖的已知漏洞默认不深扫（需 go.mod/package.json + 版本比对）。
5. **无源码黑盒**：无 maintainer_url，只能解包，二进制内部行为无法静态审计。

> 注：加壳/混淆/反调试已独立为「混淆/反分析」维度（可检测），不计入「未知风险」。

**处理原则**：未知风险单独列出；「latest 镜像漂移 / 无源码黑盒」直接给 **20-40 的 Uncertainty 安全分**，并在结论里写明「以下风险点无法静态确认，建议动态验证」。

## 交付格式（每个应用）

```
### <appname@source> · 综合安全分 62 · 🟡 中
| 维度 | 安全分 | 依据 |
| 安全性（恶意风险） | 90 | 未发现恶意模式 |
| 权限 | 15 | run-as root + systemd |
| 漏洞 | 60 | 弱默认口令 666 |
| 暴露面 | 70 | 单端口 |
| 供应链 | 30 | shuangji66 家族搬运 |
| 未知风险 | 40 | 无源码黑盒 |
| 混淆/反分析 | 50 | UPX 加壳 |
| 数据隐私/外联 | 80 | 无外联 |
```
