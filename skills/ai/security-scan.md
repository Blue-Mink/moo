# 应用安全扫描（静态）

> 能力文档：应用安全性分析与评估。把静态信号规则表操作化，用 `fpk_inspect` 只读解包逐项核对。

## 1. 硬纪律（本能力专属，先于一切步骤）
- 只分析**已在本机**的 FPK 文件（FPK 下载目录 / 已装应用目录）；**不新下载未信任包、不执行、不起容器验证**（动态分析风险不可控）。
- 结论固定标注「**静态分析，供参考非裁决**」；不做公开评分排行（避免争议与打草惊蛇）。
- 喂模型前脱敏：脚本 / compose / manifest 内容中的凭据特征串替换为 `***`。
- conversun/fnos-apps（去重排除集成员）**在安全评估范围内**——去重排除 ≠ 安全排除；官方源应用同样在范围内。

## 2. 静态信号规则表（fpk_inspect 解包后逐项核对）
| 维度 | 检查项 | 风险信号（命中=标注） |
|---|---|---|
| manifest | `privilege`（root/user） | root 运行 = 标注（说明理由，很多系统类应用合理） |
| manifest | `api-scope` 数量与内容 | scope 越宽越警（逐个列出） |
| manifest | install_type / platform | 与源声明不一致 = 标注 |
| docker-compose | `privileged: true` | **特权容器 = 高** |
| docker-compose | `network_mode: host` | host 网络 = 高 |
| docker-compose | 端口暴露 | 暴露声明 service_port 之外的端口 = 标注 |
| docker-compose | 挂载 | 挂载宿主敏感目录（/etc、/var/run、非 /vol*/@app{data,conf,meta,home} 的路径）= 高 |
| 生命周期脚本 | `curl … \| sh` / `wget … \| sh` | 管道执行 = 高 |
| 生命周期脚本 | base64 解码后执行 | 混淆执行 = 高 |
| 生命周期脚本 | `rm -rf`（超出应用自身目录） | 破坏性 = 高 |
| 生命周期脚本 | 写 crontab / ssh key | 持久化 = 高 |
| 生命周期脚本 | 外联可疑域名（应用声明的 CDN / API 之外） | 标注 + 列域名清单 |
| data-share | 共享目录范围数量 | 越宽越警 |

## 3. 执行步骤
1. 定位目标应用的 FPK / 已装目录（从下载目录与已装列表取路径，不猜测）；
2. `fpk_inspect` 只读取 manifest / docker-compose.yaml / cmd/* / config/*；
3. 按 §2 规则表逐项核对；每条命中引用 **文件 + 行号 + 原文**（已脱敏）；
4. 风险级别：**低**（无命中或仅轻微标注）/ **中**（1-2 条中风险信号）/ **高**（任一高风险信号）；
5. 按 §4 模板输出报告。

## 4. 报告模板
```
# 应用安全扫描报告
应用：{display_name}（{appname}）v{version} | 源：{source} | 扫描时间：YYYY-MM-DD HH:MM
## 结论：风险 {低/中/高}（静态分析，供参考非裁决）
## 命中明细
| 维度 | 检查项 | 命中内容（文件:行号） | 风险级别 | 说明 |
## 外联域名清单（如有）
## 未扫描项（如：容器运行时行为、未解包的层）
## 建议（如有高风险）
（只建议用户自行处理：停用/卸载/联系源作者/改用官方源——决定权永远在用户）
```

## 5. 边界
- 按需扫描（用户点名）为主，不主动全量扫已装应用；
- 扫描不改任何应用 / 源 / 文件状态（纯只读）；
- 发现高风险 ≠ 自动处置：只呈现 + 建议，用户决定。
